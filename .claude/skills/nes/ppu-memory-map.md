# PPU Memory Map — Full Reference

The PPU has its own 14-bit address bus (16 KiB address space, $0000–$3FFF),
completely separate from the CPU bus. The CPU accesses PPU memory via
PPUADDR ($2006) and PPUDATA ($2007).

## $0000–$1FFF: Pattern Tables (8 KiB)

### $0000–$0FFF: Pattern Table 0 ("left")
### $1000–$1FFF: Pattern Table 1 ("right")

- Typically mapped to CHR-ROM or CHR-RAM on the cartridge
- Mappers can bank-switch these regions (e.g., MMC3 can switch 1 KiB or 2 KiB banks)
- Codemasters games always use CHR-RAM — game code copies tile data here

### Tile Format

Each 8×8 tile is 16 bytes (2 bit planes):

```
Plane 0 (bytes 0-7):  Each byte = 8 pixels, bit = low bit of color index
Plane 1 (bytes 8-15): Each byte = 8 pixels, bit = high bit of color index
```

Combined: each pixel has a 2-bit color index (0-3).
- Index 0 = transparent/backdrop
- Indices 1-3 = colors from the assigned palette

Pattern table contains 256 tiles (16 bytes × 256 = 4096 bytes = $1000).

### Tile Address Calculation
```
tile_addr = pattern_table_base + (tile_index × 16) + row
  where: pattern_table_base = $0000 or $1000
         tile_index = 0–255
         row = 0–7 (plane 0) or 8–15 (plane 1)
```

## $2000–$2FFF: Nametables (4 KiB logical, 2 KiB physical)

### Nametable Layout

Each nametable is 1024 bytes:
- 960 bytes: 30 rows × 32 columns of tile indices
- 64 bytes: attribute table (palette assignments)

| Address | Nametable |
|---------|-----------|
| $2000–$23FF | Nametable 0 |
| $2400–$27FF | Nametable 1 |
| $2800–$2BFF | Nametable 2 |
| $2C00–$2FFF | Nametable 3 |

The NES only has 2 KiB of internal VRAM (CIRAM), providing 2 physical
nametables. The other 2 are mirrors, controlled by cartridge wiring:

### Mirroring Types

**Horizontal mirroring** (vertical arrangement, for horizontal scrolling):
```
NT0 ($2000) = NT1 ($2400) → CIRAM page 0
NT2 ($2800) = NT3 ($2C00) → CIRAM page 1
```

**Vertical mirroring** (horizontal arrangement, for vertical scrolling):
```
NT0 ($2000) = NT2 ($2800) → CIRAM page 0
NT1 ($2400) = NT3 ($2C00) → CIRAM page 1
```

**Single-screen** (mapper-controlled, e.g., Fire Hawk):
```
All four nametables → same CIRAM page (0 or 1)
```

**Four-screen** (extra 2 KiB VRAM on cartridge):
```
Each nametable is independent
```

### Attribute Table

Each attribute table is 64 bytes, covering the nametable in 2×2 tile (16×16 pixel) blocks.
Each byte controls a 4×4 tile (32×32 pixel) area:

```
7654 3210
|||| ||++- Palette for top-left 2×2 tile area
|||| ++--- Palette for top-right 2×2 tile area
||++------ Palette for bottom-left 2×2 tile area
++-------- Palette for bottom-right 2×2 tile area
```

This encoding means BG palette resolution is 16×16 pixels — a key constraint
of NES graphics.

### Attribute Byte Address Calculation
```
attr_addr = nametable_base + $03C0 + (tile_y / 4) * 8 + (tile_x / 4)
```

## $3000–$3EFF: Mirror of $2000–$2EFF
Unused mirror due to incomplete PPU address decoding.

## $3F00–$3FFF: Palette RAM (32 bytes + mirrors)

### Background Palettes ($3F00–$3F0F)
```
$3F00: Universal backdrop color (shared across all palettes)
$3F01–$3F03: BG Palette 0, colors 1-3
$3F04: Mirror of $3F00 (backdrop)
$3F05–$3F07: BG Palette 1, colors 1-3
$3F08: Mirror of $3F00
$3F09–$3F0B: BG Palette 2, colors 1-3
$3F0C: Mirror of $3F00
$3F0D–$3F0F: BG Palette 3, colors 1-3
```

### Sprite Palettes ($3F10–$3F1F)
```
$3F10: Mirror of $3F00 (backdrop)
$3F11–$3F13: Sprite Palette 0, colors 1-3
$3F14: Mirror of $3F00
$3F15–$3F17: Sprite Palette 1, colors 1-3
$3F18: Mirror of $3F00
$3F19–$3F1B: Sprite Palette 2, colors 1-3
$3F1C: Mirror of $3F00
$3F1D–$3F1F: Sprite Palette 3, colors 1-3
```

- Each palette entry is 6 bits (0–63), indexing the NES master palette
- Color index 0 in any palette is always transparent and shows the backdrop
- Palette RAM is internal to the PPU and reads bypass the read buffer
  (no priming read needed, unlike normal VRAM reads)
- $3F20–$3FFF mirrors $3F00–$3F1F

### NES Master Palette

The NES has a fixed 64-color master palette (generated by NTSC/PAL video
circuitry). Colors are not RGB — they are luma+chroma combinations. The exact
RGB values depend on the TV and region. Common palette files (e.g., .pal) map
these 64 indices to RGB approximations.

**Warning**: Color $0D generates a signal level below the NTSC sync threshold
("blacker than black"). Many TVs interpret this incorrectly. Most games avoid
it. Codemasters games notoriously use $0D — later PAL versions replaced it with
$0E.

## PPU Rendering Pipeline (Key Concepts for RE)

### Scanline Timing
- 262 scanlines per frame (NTSC), 312 (PAL)
- 341 PPU cycles per scanline
- Scanlines 0–239: visible
- Scanline 240: post-render (idle)
- Scanline 241: vblank begins, NMI triggered (if enabled)
- Scanlines 242–260: vblank (safe to access PPU memory)
- Scanline 261: pre-render

### Sprite Evaluation
- PPU evaluates all 64 OAM entries per scanline
- Maximum 8 sprites per scanline (additional sprites are dropped)
- Sprite 0 hit: when a non-transparent pixel of sprite 0 overlaps a
  non-transparent BG pixel. Used for split-screen effects.

### VRAM Access During Rendering
- **Do NOT** access PPUDATA or OAMDATA while rendering is active
  (scanlines 0–239 and pre-render scanline)
- All VRAM updates must happen during vblank or with rendering disabled
- OAM should be updated via DMA ($4014) during vblank, not byte-by-byte
